## Behavior comparison

| Area | Fork changes | Assessment against maintained branch |
|---|---|---|
| Registration and UI | Both forks use TOPBAR file menus. Leoluis adds batch-import UI and catches registration/unregistration failures independently. | Menu migration is already present. Current class/menu bookkeeping makes reload and partial failure testable; catching each error and continuing can leave a partially enabled add-on while reporting success. No registration fix is missing. |
| Blender properties and context | Leoluis assigns many Blender properties with legacy assignment syntax, defaults imports to clearing the scene, and performs broad selection/mode operations. | The maintained branch uses property annotations, explicit context APIs and scene-scoped clearing. Its tests cover 4.4.3 and 5.2.2. No 5.2 fix was missing. |
| Import and failure handling | Vai's alternate branch coerces unexpected skeleton/weight option values to permissive defaults; both forks retain broad exception handling in import paths. Leoluis' batch importer depends on selected objects to collect import results and does not implement its advertised texture conversion. | Current option values are already plain operator enum strings; unknown weights should fail rather than silently change representation. The compatibility forks provide no regression for these fallbacks or batch behavior. Preserve explicit parser errors and the incomplete-import export guard. |
| Armature and normals | Leoluis uses current object linking/selection calls and `_safe_set` compatibility helpers for visibility properties. Its normal setter lacks this branch's validation and targeted reverse-wound duplicate-triangle sharp-edge handling. | The maintained armature path passes tests on both Blender versions; Leoluis' fallback helpers do not establish a missing fix. The body normal fix is tested on both versions. The remaining arm mismatch is on a zero-area face and stays documented as PARTIAL. No independently validated armature/normals fix was found in either fork. |
| Materials | Leoluis still creates `ShaderNodeSeparateRGB` / `ShaderNodeCombineRGB` and accesses Principled inputs using numeric indices such as `[0]`, `[5]`, and `[7]`. | Current code already uses Separate/Combine Color in RGB mode and named Principled sockets; Blender 5.2 material tests cover these node links. Fork changes would reintroduce fragile/legacy node handling. |
| Export and real-file safety | Leoluis' export operator calls scene cleanup and `bpy.ops.object.transform_apply` before encoding. Its code has no opaque source replay or edit fingerprint. The commit deletes `blender/BlenderOpaqueBounds.py` and all committed `tests/`. | These operations can mutate scene objects or remove scene data before export succeeds. Reconstructing a real file without preserving unresolved global bbox records can lose data. This directly conflicts with the maintained branch's byte-exact unchanged replay and fail-closed edits; do not adopt. |
| Format and regression coverage | Leoluis tracks CPython 3.14 `__pycache__` files and its rewrite adds a batch operator. It removes this branch's regression suite; its `scripts/tests.py` does not cover opaque replay or edit guards. | Generated cache files are not source or compatibility fixes. Batch import is separate functionality and lacks preservation regression coverage. The maintained branch keeps the format guards and tests; no coverage should be dropped. |
| Licensing | Leoluis' commit adds an Apache-2.0 `LICENSE`, while the original upstream repository has no top-level license declaration. | A downstream commit alone does not establish authority to relicense upstream code or bundled programs. This fork does not copy that license; the original rights remain a maintainer/distribution question. |

## Adoption decision

No code change from either compatibility fork is both missing here and independently justified by the current tests/evidence. Do not copy their patches. Blender menu registration, current shader node/socket handling, armature API changes, and the Blender 5.2 runtime suites are already covered by the maintained branch. Keep the alternate split-weight fallback, legacy RGB nodes and Principled indices, destructive export setup, and missing preservation/tests out of this branch.

The `nn10n10/Mod3-MHW-Importer` public repository currently points `master` at the upstream base `364c260`; it does not yet contain this compatibility branch. This review changed only the local maintenance worktree and local review refs.
